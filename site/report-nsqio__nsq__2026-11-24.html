4. 关键设计决策（ADR）

每条固定六字段：决策 / 替代 / 代价 / 证据 / 可复用规则 / 边界·反模式。

ADR-1 · t1: 用 go-svc 统一管理三进程启停与信号

  • 决策：用 go-svc 统一管理三进程启停与信号
  • 替代：各自手写 signal.Notify 与退出逻辑
  • 代价：引入外部依赖，生命周期被框架约束
  • 证据：apps/nsqd/main.go:24
  • 可复用规则：多守护进程统一用服务框架封装启停，减少重复信号处理代码
  • 边界/反模式：单次运行即退出的 CLI 工具不适用，框架反而增加样板

ADR-2 · t2: 配置解析走 flag+TOML+options.Resolve 三层合并

  • 决策：配置解析走 flag+TOML+options.Resolve 三层合并
  • 替代：仅用命令行 flag 或仅用配置文件
  • 代价：需维护 config 结构体与校验逻辑
  • 证据：apps/nsqadmin/main.go:118
  • 可复用规则：配置优先级显式分层：默认值<配置文件<命令行，便于运维覆盖
  • 边界/反模式：配置项极少或纯库场景不必引入 TOML 层

ADR-3 · t3: 向后兼容在 flag 解析后单独函数里做默认值推导

  • 决策：向后兼容在 flag 解析后单独函数里做默认值推导
  • 替代：把兼容逻辑散落在各 flag 默认值定义处
  • 代价：多一层隐式赋值，阅读时需追踪 flagSet.Lookup
  • 证据：apps/nsqd/main.go:96
  • 可复用规则：兼容性默认值集中到解析后钩子，避免污染 flag 定义
  • 边界/反模式：无历史包袱的新项目不需要该兼容层

ADR-4 · t4: 集群元数据查询对多个 lookupd 并发 fan-out 后合并去重

  • 决策：集群元数据查询对多个 lookupd 并发 fan-out 后合并去重
  • 替代：串行逐个查询 lookupd
  • 代价：需加锁与 WaitGroup，错误聚合复杂
  • 证据：internal/clusterinfo/data.go:88
  • 可复用规则：多副本元数据源并发查询再合并，降低尾延迟
  • 边界/反模式：副本数少或强一致要求场景，并发合并会掩盖不一致

ADR-5 · t5: 部分 lookupd 失败仍返回部分结果并附 ErrList

  • 决策：部分 lookupd 失败仍返回部分结果并附 ErrList
  • 替代：任一节点失败即整体报错
  • 代价：调用方需处理 PartialErr 语义
  • 证据：internal/clusterinfo/data.go:113
  • 可复用规则：读路径容忍部分副本失败，返回可用数据加错误明细
  • 边界/反模式：写路径或需要全量视图的决策场景不可降级返回

ADR-6 · t6: nsqadmin 用 httprouter 集中注册路由并统一 Decorate 中间件

  • 决策：nsqadmin 用 httprouter 集中注册路由并统一 Decorate 中间件
  • 替代：各 handler 内自行做日志与错误包装
  • 代价：路由表集中，新增端点需同步注册
  • 证据：nsqadmin/http.go:78
  • 可复用规则：HTTP 层用统一装饰器包裹日志/版本/错误，保持 handler 纯净
  • 边界/反模式：需要按路由差异化中间件链时，集中装饰会变僵硬
