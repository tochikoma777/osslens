## 0. TLDR：红线速查

### 0.1 工作方式（先看这个）

1. **你是执行者**，项目负责人是决策者。**每个里程碑结束后停下**，输出验收报告，不要开始下一阶段。
2. **一次只做一件事**。给你的待确认项超过 1 个 = 节奏失控的信号。
3. **不确定的列出来问**，不要自作主张。发现文档冲突 → 停下 + 引双方原文上报，**不得自行按低优先级文档执行**。
4. **全程中文回复**（技术术语、代码、路径除外）。

### 0.2 十二条最高红线（违反即返工）

| #    | 红线                                                         |
| ---- | ------------------------------------------------------------ |
| 1    | **不改 `设计方案.md` / 本手册 / `文档维护日志.md`**（项目负责人出全量并覆盖，你只读） |
| 2    | **off 档严禁任何 LLM 调用**（含发往模型服务商的网络请求）；断言必须是"代码根本没发请求"，**不是"用 mock 顶掉后断言 0"** |
| 3    | **无凭据不报错**：未配置 api_key / base_url / model 任一 → 自动降级 `off`，**退出码 0** |
| 4    | ★ **外部资料 fail-closed**：判定必须用"**正文是否含 ≥N 个仓库内真实路径**"（默认 N=3），**不得用"能否访问"**；未命中 → 返回 None 并在报告标注「外部资料：不可用（未索引）」，**绝不回退成模板化页面** |
| 5    | ★ **无证据不得写入特征卡**：`parallel.hits` / `cache.hits` / `hardware.*` 的每个 `true` **必须带 evidence（文件+行号+片段）**；带不出就置 `false` |
| 6    | **真源 append-only**：`ledger/selected.jsonl` / `pool/pool.jsonl` / `costs/costs.jsonl` 只追加不覆盖；`patterns/` 只追加修订（保留旧 ID 作 alias）。**任何删除类操作先列清单 + 停下等确认** |
| 7    | **禁止 `git clean -fd`**（未跟踪的过程性文档会被一次清空）   |
| 8    | ★ **幂等：时间不来自运行时钟**。报告时间 = `--as-of`；未传则取输入快照的 `fetched_at`，**不是 `datetime.now()`** |
| 9    | ★ **幂等：集合必须确定性排序**。模块 / 依赖边 / 贡献者等一律排序后输出（路径升序；计数值降序 + 路径升序 tie-break）；浮点 `round(x,4)`；JSON `sort_keys=True` |
| 10   | ★ **降级必须双写留痕**：报告头部「运行元数据」块（requested / actual / reason / quota_state）+ `costs.jsonl` 追加一条。**静默降级 = 失控** |
| 11   | ★ **模式召回零 LLM**，且必须输出**三分类**（采用 / 未采用=反例候选 / 不适用）。无反例位的模式条目禁止入库 |
| 12   | ★ **打分只用于排序，绝不用于升档**。按打分自动升档 = 循环论证（自己造的指标决定自己花多少钱） |

### 0.3 本项目特有的六条追加红线

| #    | 红线                                                         |
| ---- | ------------------------------------------------------------ |
| 13   | ★ **外部资料快照带来源四元组**：写入 `_sources/<repo>/<name>-<date>.md` 时头部必须有 `source / url / fetched_at / sha256`。**结构分离**：原文与 LLM 生成内容不得混在同一段 |
| 14   | ★ **上下文裁剪发生在调用之前**（预估 → 组装 → 校验），**绝不在生成中途降质**。预算不够 = 裁上下文或少做，不是降输出质量 |
| 15   | ★ **prompt 是代码资产**：放 `src/*/prompts/*.j2` / `templates/`，**不放 docs**；改 prompt 必须触发对应单测 |
| 16   | ★ **LLM 输出必须紧凑**：只返回 `id + 字段`，**不回显标题/摘要**（回显会撞 max_tokens） |
| 17   | ★ **可证伪性由代码判定，不由 LLM 输出**。LLM 不得自己说"无法验证 / 无法判断"——该结论只能由硬条件产生 |
| 18   | ★ **不可证伪的洞察必须标注为「观点」**，不计入规律库统计     |
| 19   | ★ **测试断言不得打到注释或说明文字**（他项目已两次踩中：脚注含"★"导致 `assert "★" in output` 恒真）。断言必须针对**真实输出结构** |
| 20   | ★ **时间驱动逻辑必须写跨天/跨月时序单测**（用受控时钟推进）。只测当天 = 没测 |

### 0.4 三个最容易做错的点

| 点                 | 常见错误做法           | 正确做法                                                     |
| ------------------ | ---------------------- | ------------------------------------------------------------ |
| **外部工具未命中** | 页面 HTTP 200 就当命中 | 必须判定正文含 ≥3 个仓库内真实路径；OpenLake 案例：200 + 显示仓库名 + 正文零专属内容 |
| **档位降级**       | 降级了但没留痕         | 双写：报告元数据块 + `costs.jsonl`                           |
| **模式入库**       | 只收正例               | 必须带反例位；召回的"未采用"就是反例来源                     |

## 1. 工作方式

### 1.1 阶段内流程

```
读 SSOT（指定章节）→ 实现 → 自测门禁 → 输出验收报告 → 停下等确认
```

**不要跳步**。尤其不要"顺手"做下一阶段的事。

### 1.2 读文档的方式

- **不要全量读设计方案**。读项目负责人**点名的章节**。
- 每个里程碑开场，项目负责人会给出「本次重点章节」。
- 常用点名：§2 档位决策 · §3 特征卡 · §4 模式召回 · §6 打分与边界 · §7 幂等两坑 · §8 数据布局 · §9 成本观测

### 1.3 提交与文档

| 顺序 | 步骤                                     |
| ---- | ---------------------------------------- |
| 1    | 代码完成 → 自测全绿                      |
| 2    | **提交 + 打 tag**（如 `l0`）             |
| 3    | 项目负责人刷新 SSOT 与 `文档维护日志.md` |
| 4    | 你**不要**改 SSOT 与维护日志             |

**为什么这个顺序**：维护日志要记录「文档版本 ↔ tag」。代码没提交就写不出 tag 列——**写不出来就说明顺序错了**。
★ **禁止 force 更新 tag**。

## 2. 红线详解

### 2.1 数据真实性类

| 红线                                 | 说明                                                         |
| ------------------------------------ | ------------------------------------------------------------ |
| **禁止伪造 fixtures**                | 需要真实响应时真实抓取；抓不到就 `pytest.skip(reason=...)` 并写明原因 |
| **探测结果必须真实**                 | 数据源手册只能从真实响应摘取字段表与片段                     |
| ★ **不用"本地测不到"推断"源不可用"** | `availability` 描述**源本身是否公开可用**，不是"从我这儿能不能访问"。本地失败 → 加 `*_base_url` 配置项，不可达时 warning + 跳过，**不把网络问题编码成源属性** |

### 2.2 LLM 相关类

| 红线                                | 说明                                                         |
| ----------------------------------- | ------------------------------------------------------------ |
| **off 档零调用**                    | 客户端为空实现，断言 0 请求                                  |
| **三级降级阶梯**                    | `json_schema → json_object → plain`；**plain 是万能兜底**    |
| **降级状态按 (model, format) 记忆** | 不能全局布尔（不同模型支持情况不同，全局会连坐）             |
| **超时分层**                        | fast / strong 分别设置；推理型模型输出更长                   |
| **结果持久化**                      | 同一输入不重复生成（内容 hash + TTL + 失效条件）             |
| **调用前后都记账**                  | 调用前预估过闸门，调用后按实际 token 记 `costs.jsonl`        |
| ★ **判废规则**                      | 空输出或 `tokens_out` 顶格 → 判废；**连续 2 次判废即中止本轮**（防止系统性失败烧钱） |

### 2.3 输出与文件类

| 红线                 | 说明                                       |
| -------------------- | ------------------------------------------ |
| **原子写入**         | 临时文件 + rename，避免读到半截文件        |
| **空态显式**         | 无数据显示 `—` 或"暂无"，不静默省略        |
| **外部资料结构分离** | 快照原文与生成内容**分区块**，不混排       |
| **文件名清洗**       | 非法字符（`/ \ : * ? " < > |`）→ `-`       |
| **Mermaid 内嵌**     | 依赖图以 Mermaid 代码块内嵌 MD，输出自包含 |

### 2.4 工程类

| 红线                                  | 说明                                             |
| ------------------------------------- | ------------------------------------------------ |
| **单源失败不影响退出码**              | 可选源失败 → 退出码 0 + 记 `degraded`（带原因）  |
| **不引入 openai SDK**                 | httpx 直连（SDK 会阻碍 mock）                    |
| **统一走 HttpClient**                 | 限速 / 重试 / 代理 / UA 复用；LLM 层关 HTTP 缓存 |
| **配置只从 config.yaml + 环境变量读** | 环境开关必须 `${ENV}` 占位符；代码内不硬编码阈值 |
| **mypy strict**                       | 不用 `# type: ignore` 掩盖，必要时用 `cast`      |
| **不用 `ubuntu-latest`**              | 固定 `ubuntu-24.04`                              |
| **禁止 force push**                   | push 前先 rebase                                 |

## 3. 命令集（契约）

> ★ **v1.1 修正**：命令前缀原写 `osa`，与项目名 `osslens` 及实际入口不一致。
> 统一为 **`python -m osslens`**。完整 flag 以 `python -m osslens <cmd> --help` 为准，本表只列常用项。

```bash
python -m osslens init                  # 目录骨架 + config 骨架
python -m osslens pool add <owner/repo> [--channel hot|classic|watchlist]
python -m osslens pool list             # 分通道打分排序
python -m osslens pool eligible         # 深挖候选（热点需过观察期）
python -m osslens analyze <owner/repo>  [--depth auto|off|fast|strong] [--channel ...] \
        [--domain ...] [--as-of ISO] [--dry-run] [--no-ledger]
python -m osslens abstract              # 规律抽象（批量触发）
python -m osslens cost [--as-of ISO]    # 成本台账
python -m osslens site                  # L4 静态站点
```

**退出码契约**：

| 码   | 含义                                              |
| ---- | ------------------------------------------------- |
| 0    | 完成（**可能已降级**，降级在报告与 costs 中可见） |
| 1    | 配置错误                                          |
| 2    | 参数错误                                          |

> ★ **可选源失败、配额耗尽、预算拦截、未配 key 一律退出码 0**。非 0 只能是真失败。

## 4. 报告结构（★ 写死，见附录 A）

报告结构（v3，2026-11-19 起）：**导读 → 1 项目定位与目标 → 2 架构全景 → 3 核心抽象与契约 → 4 关键设计决策（ADR）→ 5 扩展与改造路径 → 6 经验卡 → 附录 A（证据索引与未知项）→ 附录 B（许可证 / 维护 / 工程 / 成本）**。正文必须区分 `[事实]` / `[判断]` / `[未获得]`；ADR 固定六字段（决策 / 替代 / 代价 / 证据 / 可复用规则 / 边界·反模式）；经验卡缺 rule 时留空，不得用通用建议填充。完整契约与版本历史见 `docs/报告模板-v3.md` 与 `docs/报告模板-版本记录.md`。
`off` 档的洞见位**显式填 `—`**，不得省略该段、不得用套话填充。

## 5. 里程碑（以任务卡为准）

| 阶段   | 目标                                                  | 完成判据                                                     |
| ------ | ----------------------------------------------------- | ------------------------------------------------------------ |
| **L0** | 采集 + 建池 + 去重 + **off 档体检报告**               | 对 1 个真实仓库跑出完整体检报告（**零 LLM**）                |
| **L1** | 特征卡 L0 + 依赖图 + 外部工具（fail-closed）+ fast 档 | 特征卡含证据；Mermaid 图可渲染                               |
| **L2** | 档位四层 + 预算闸门 + 成本观测 + 定时                 | `cost` 可用；配额用完能自动降级并留痕                        |
| **L3** | 模式召回 + 批量抽象 + 反例自动挖掘                    | 同 `domain.id` 簇**新增 ≥6 个真实项目**后触发第一次抽象（与设计方案 §10 一致） |
| **L4** | 静态站点（只读）                                      | 由 MD + JSON 生成，无后端                                    |

★ **L0 优先**：实测已证 off 档基于元数据层（<1 万 token）即可产出且零成本——**唯一能立刻开始积累样本又不烧钱的路径**。

## 6. 验收报告模板

**在会话输出，不落成文件**（缺项视为未完成）：

```markdown
● LX 验收报告

## 已完成
（按子项列出，不要写"完成了 LX"这种空话）

## DoD 核对
（逐条对照，标注 ✅/⚠️/❌；⚠️ 必须写明原因）

## 关键文件清单
（新增/修改，含行数）

## 测试与覆盖率
- pytest N passed（上阶段 M，+X）
- ruff / ruff format / mypy strict
- 覆盖率：核心模块分别列出 + TOTAL

## 真实运行证据
（不是单测，是实际跑出来的输出；off 档要有 llm 调用 = 0 的证明）

## 遇到的坑与解决

## 需要决策的问题（≤1 个）

## 下一步
（明确写"未开始下一阶段"）
```

**三条硬要求**：

1. **真实运行证据必须有**（单测通过 ≠ 功能真的产出过非空内容）
2. **诚实暴露局限**（如"只做到连续两次，没做到连续两天"）——这比漂亮的完成度有价值得多
3. **幂等自证**：连续两次同 `--as-of` 运行，产出字节一致（排除运行时刻时间戳）
