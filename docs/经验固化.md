## E-001 · 判定"某个源不可用"之前，必须穷尽它的全部入口

**结论**：任何"源不可用 / 未索引 / 不支持"的结论，都必须附上**试过哪些入口、各自返回什么**。
只试了一个入口就下结论 = 不可信，且极易导致架构误判。

### 事实经过（L1，2026-11-03，可复现）

| 步骤 | 动作 | 结果 | 当时的错误结论 |
|---|---|---|---|
| 1 | `GET https://deepwiki.com/deepseek-ai/DeepEP` | HTTP 429 + `Vercel Security Checkpoint` | "HTML 被墙，换方案" |
| 2 | MCP `initialize` + `tools/list` | 200，工具：`ask_wiki_question` / `read_wiki_contents` / `read_wiki_structure` | — |
| 3 | 只调 `read_wiki_structure` | 返回**页面标题列表**（无文件路径） | ❌ "MCP 不含仓库路径，不能用于命中判定" |
| 4 | 于是改走 HTML 抓取 | 不稳定（时好时 429） | ❌ 差点把不稳定通道当成唯一方案 |
| 5 | 复核：调 `read_wiki_contents` | 返回 **196KB 正文**，含 **10 个仓库内真实路径** | ✅ 这才是补充件 T5 指定的正路 |

**根因**：把"入口 A 不含证据"误当成"源不含证据"；把"一次 429"误当成"源不可用"。
两者都属于**用一个样本否定一个集合**。

### 判定式（写结论时的最低要求）

> 源 `S` 不可用 ⇔ 已尝试 `S` 的**全部已知入口**，且每个入口的失败都被记录下来。

结论必须形如：

```
source: deepwiki
tried:
  - html   https://deepwiki.com/o/r        → 429 Vercel checkpoint
  - mcp    tools/call read_wiki_structure  → 200，仅标题，无路径（不能判命中）
  - mcp    tools/call read_wiki_contents   → 200，196KB，含 10 个真实路径  ✅
verdict: available
```

反例（**禁止**这种写法）：

```
❌ "DeepWiki 不可用"            ← 试了哪个入口？返回什么？
❌ "MCP 不支持，返回的是标题"     ← 只试了三个工具中的一个
❌ "本地访问失败 → 源不可用"      ← 网络可达性 ≠ 源可用性
```

### 边界（这条规则不覆盖的情况）

- **入口清单本身未知**时，先列清单再逐项试；不能因为"不知道还有没有别的入口"就跳过。
- **确定性失败**（401/402/404、明确的 `isError`）**一次即足**，不需要穷举；本规则针对的是
  "疑似不可用"（429/超时/空页/模板页）这类**可能只是单个入口的问题**。
- 穷举有成本上限：入口数 > 5 或单次耗时 > 60s 时，允许"试完前 N 个 + 明确记录未试项"，
  但结论要降级为「**部分验证**」，不得写成「不可用」。

### 本项目的落地检查

| 场景 | 检查点 |
|---|---|
| 新增数据源 | 探测代码必须能列出"试过哪些入口"，并写进报告「外部资料」的原因字段 |
| 报告里的 `blocked` / `unavailable` | 原因必须包含 HTTP 状态或错误类型，不能只写"不可用" |
| 写进《数据源手册》的"未获得" | 必须写明"试过什么、为什么不行"，参考 §6 的 19 条格式 |
