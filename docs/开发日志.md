### 3. 关键决策与依据

| # | 决策 | 依据 |
|---|---|---|
| D1 | **快照按 `as_of` 日期落盘，重跑复用** | 幂等要求"同一输入 → 同一字节"。若每次重跑都抓实时数据，stars 一变报告就变，`test_report_is_byte_identical` 会永远红。快照 = 输入，输入不变则输出不变 |
| D2 | **特征卡的 `deps.*` / `loc_total` / `internal_edge_count` 置 `null`，渲染 `—`** | 这些要么需要读源码、要么需要清单解析。L0 是元数据层，编一个 `0` 等于宣称"没有依赖"，是伪造（红线 #5）。`null` + 报告「已知限制」逐条说明 |
| D3 | **`used_by` / `issue_close_ratio_90d` 标 `unavailable` 而非 `0`** | GitHub 无公开 used_by API；issue 比例要 search API（10 次/分钟）。`0` 会被误读成"没人用" |
| D4 | **观察期先于增量门槛判定** | 只有 1 次观测时 delta 必为 0，若先判 delta，原因会显示"增量不足"——真正的原因是"还没开始观察"。原因错了比结论错更危险 |
| D5 | **实现能力检查放在凭据之后、配额之前** | L0 没有 LLM 实现，先判配额会得出"因配额降级"的假原因。能力缺失是**前提**，不是预算层 |
| D6 | **`costs.jsonl` 追加前比对已有记录，完全相同则跳过** | 同 `as_of` 重跑会产生逐字节相同的 downgrade 事件，重复追加会让「降级次数」虚高。跳过仍是 append-only（不修改、不删除） |
| D7 | **`pool add --as-of` 同时作为观测时刻** | 否则入池不可复现（观测时间来自运行时钟）。显式给 `--as-of` 时，快照时间、观测时间、可复现性三者一致 |
| D8 | **报告「上下文组装」表在 off 档填 `—` + 合计 0** | 附录 A 有这个块；off 档确实不组装。填估算数字等于假装做过裁剪 |

### 3. 踩过的坑

1. **DeepWiki 不稳定**：`httpx` 直连曾返回 429（Vercel Security Checkpoint），同一环境下又成功返回正文并判定 hit。已按 fail-closed 处理：429 → `blocked`，报告写「未获得 + 原因」，**不伪装成"未索引"**。
2. **MCP 曾被我误判**：只测了 `read_wiki_structure`（标题列表），就得出"MCP 不含路径"的结论并改用 HTML；HTML 随后被 Vercel 校验拦成 429。重测 `read_wiki_contents` 才发现正文有 10 处真实路径。**教训：判定"某源不可用"之前，必须把它的全部工具/入口试完**。
3. **累计成本双计**：首次用 `run_id` 排除本次事件，但调用事件的 `run_id` 用了 `purpose` 作 reason，与账本计算不一致 → 报告显示 2 倍。改为按 `(repo, as_of, purpose)` 排除。
4. **成本行随缓存命中变化**：「本次 ¥0.0476（1 次调用，api）」→ 重跑变「0 次调用，cache」→ 字节不一致。改为与分析进程无关的口径。
5. **`quota_state` 随调用次数漂移**：第一次 0/3、第二次 1/3。改为排除本次分析自身调用后稳定为 0/3。
6. **`--no-sources` 会跳过已缓存的切片**：单测里预置 manifest 却传 `--no-sources`，导致图始终为空。测试改为不传该 flag（有缓存即不联网）。
7. **`parse_insight` 把 `items: []` 判废**：空数组 = 没有可证伪结论，按"空输出"处理是正确的，但测试初版误用了空数组。
8. **`ENTRYPOINT_NAMES` 在 collect/featcard 重复定义**：两处用途不同（选片 vs 标记入口），暂未合并，后续要统一。
