# 成本预算

> **性质**：成本口径与台账说明（证据层，非 SSOT）。权威顺序同《数据源手册》。
> **原则**：单价只来自 `config.yaml`；代码内**不出现任何价格字面量**（设计方案 §9）。
> **核对日期**：2026-11-03（DeepSeek 官方中文定价页 + 英文页交叉验证）。

---

## 1. 单价表（人民币 / 1M tokens，取**高峰价**单值）

| 模型 | 缓存命中 | 输入未命中 | 输出 |
|---|---:|---:|---:|
| `deepseek-flash`（V4.1-Flash-1017） | ¥0.04 | ¥2.00 | ¥8.00 |
| `deepseek-v4-pro`（V4-Pro-0813） | ¥0.30 | ¥9.00 | ¥27.00 |

- **来源**：`https://api-docs.deepseek.com/zh-cn/quick_start/pricing/`（人民币）与
  `https://api-docs.deepseek.com/quick_start/pricing`（USD），两页隐含汇率 6.67–6.82，互为印证。
- **为什么取高峰价**：官方高峰时段（工作日 09:00–12:00 / 14:00–18:00 北京时间）是低谷的 2 倍，
  且**排除中国法定节假日**——做双值需要节假日日历 + 时区 + 边界测试，L1 复杂度陡增；
  闸门按 token 计数、不按金额，高估只会更早拦截，不会漏拦。
- **偏差方向**：台账会**高估约 2 倍**（低谷实际约为表中一半）。该偏差在报告「成本说明」行显式可见。

## 2. 估算 → 实测（分列，不混写）

| 项 | 估算 | 实测（2026-11-03，DeepEP） | 偏差 |
|---|---:|---:|---:|
| fast 输入 token | 17,354（按字符数 /4） | **21,803**（`usage.prompt_tokens`） | **+25.6%** |
| 其中缓存命中 | 0 | **896** | — |
| fast 输出 token | 未估 | **501** | — |
| fast 单次费用 | ¥0.0347 | **¥0.0459** | +32% |

**结论**：`len(text)//4` 只能当量级估算，**不得**用于对账；对账一律用 API 回显的 `usage`。
估算偏差主要来自 system prompt、文件清单与 JSON 包装（估算只覆盖用户正文）。

| 档位 | 单次费用 | 依据 |
|---|---:|---|
| fast（实测） | **¥0.0459** | 3 次真实调用，见 §4 |
| strong（估算，**未实跑**） | ≈ ¥1.12 | 假设 100k 输入 + 8k 输出 × pro 单价；L2 起按实测回填 |

**周/月/年（1 strong + 3 fast 的节奏）**：
周 ≈ ¥1.25 · 月 ≈ ¥5.4 · 年 ≈ **¥65**（低谷约一半 → 年 ≈ ¥33）。

## 3. M1 · 报告里的成本说明块

**位置**：`## 运行元数据` 块内追加三行，**不新增第六区块**（避免改 SSOT 报告结构）。

```
| 成本说明 | 本次 ¥0.0459（模型调用 1 次）；输入 21,803 tok / 命中 896 tok / 输出 501 tok |
| 累计 | 本周 ¥0.0459 / 22,304 tok；本月 ¥0.0459 / 22,304 tok |
| 单价 | deepseek-flash 输入未命中 ¥2/M · 缓存命中 ¥0.04/M · 输出 ¥8/M（官方中文页，核对 2026-11-03，取高峰价；低谷约为一半） |
```

★ **口径（重要）**：报告描述「**本次分析的成本**」，与「本次进程是否命中结果缓存」无关。
同一 `--as-of` 重跑时，成本行不变（否则幂等失效）。进程级的真实花钱情况看 `cost` 命令。

该口径已**写进报告本身**（`运行元数据` 块第 4 行）：

```
| 口径 | 成本说明=**本次分析**的成本（同 as-of 重跑不变，幂等优先）；账户实际支出看 `cost` 命令的全局台账，两者不一致是设计，不是 bug |
```

→ 读者不会再把它误读成"台账漏记"。

## 4. M3 · 真源 vs 缓存

| 文件 | 性质 | 说明 |
|---|---|---|
| `data/costs/costs.jsonl` | **真源**（append-only，跟 git 走） | 每次调用/降级/拦截/缓存命中都记一行 |
| `data/llm_cache/<sha256>.json` | 缓存（可丢弃） | 同输入复用，删掉只会多花钱，不会丢结论 |
| `data/snapshots/**/src/` | 缓存（可丢弃） | 由 commit 决定，可重建 |

**坏记录**：解析失败 / 费用为 `null` / 时间非法 → **打印提示，不静默跳过**（少算比多报更危险）。

**台账实测（截至 2026-11-03）**：

```
本周 tokens 67,168（缓存命中 1,152），费用 0.1421，降级 2 次，预算拦截 0 次
按档位 fast=3；按用途 fast_insight 3 次 67,168 tok
```

> 3 次调用来自 L1 开发期的三次迭代（改 prompt/图结构各触发一次真实调用），
> 不是产品缺陷，保留在台账里作为真实审计痕迹。

## 5. M2 · 异常判定（只标注，不阻断，退出码恒 0）

| 规则 | 阈值 | 落地 |
|---|---|---|
| 周用量 | > 周额度 × 50% | 报告「成本异常」行 + `cost` 打印 |
| 月用量 | > 月额度 × 80% | 同上 |
| 单次突增 | 本次 > 同仓库历史调用中位数 × 3 | 同上；**中位数为 0 时跳过**（不拿 0 冒充） |

★ 成本异常**不写入 `degraded`**：`degraded` 只表示数据源故障，混入成本会变噪音。

## 6. 闸门与阻塞语义

| 闸门 | 位置 | 触发后 |
|---|---|---|
| L2 周配额（次数） | `depth.weekly_quota` | 降级 + 双写留痕 |
| L3 预算（token） | `depth.budget.*` | `blocked` 事件 + 报告元数据 + 退出码 0 |
| **M7 单次调用次数** | `depth.budget.max_calls_per_run`（默认 12） | 硬停 + `blocked` 事件 + 退出码 0 |
| M5 | — | **拦截后候选仍在池**，下轮可见；绝不因预算截断单次生成 |

稳态下预算闸门**从不触发**（周用量约为额度 1%），这是设计：它是保险，不是节流阀。
真正约束篇数的是 L2 周配额（strong ≤1、fast ≤3）。

## 7. M9 · 改阈值的年化义务

任何 `budget.*` / `weekly_quota` 调整，验收报告必须给「**改前 / 改后 × 365**」对比，
否则日差 0.1 元在年度尺度会被低估 36.5 倍。
