# 数据源手册

> **性质**：证据层文档（非 SSOT）。只记录**实测到的事实**与**口径**，不做设计决策。
> **维护方**：Code Agent（每阶段归并新素材）。**权威顺序**：任务卡 > CODEBUDDY > 执行手册 > 设计方案 > 本手册。
> **原则**：拿不到就写"未获得 + 原因"，**不估算、不外推、不用第三方解读补位**。
> **素材来源**（`docs/ref/`，只读）：
> - `token_result.json`（4 仓库 token 口径实测）
> - `watchlist星标活跃度复核.md`（2026-10-30，19 个仓库）

## 2. GitHub REST API

### 2.1 本项目实际调用的端点（L0，6 个）

| 端点 | 取用的字段 | 失败时 |
|---|---|---|
| `GET /repos/{o}/{r}` | `stargazers_count` `forks_count` `open_issues_count` `created_at` `pushed_at` `default_branch` `archived` `license.spdx_id` `owner.type` `size` `topics` | **必需源**，失败即整体失败（退出码 1） |
| `GET /repos/{o}/{r}/languages` | 各语言字节数 | 可选源，降级 |
| `GET /repos/{o}/{r}/contributors?per_page=100` | `login` `contributions` | 可选源，降级 |
| `GET /repos/{o}/{r}/releases?per_page=100` | `tag_name` `published_at` `draft` | 可选源，降级 |
| `GET /repos/{o}/{r}/commits?since=<as_of-365d>` | `sha` + `commit.author.date` | 可选源，降级 |
| `GET /repos/{o}/{r}/git/trees/{branch}?recursive=1` | `path` `type` `size` + `truncated` | 可选源，降级；`truncated=true` 记为截断 |

**实测用量（2026-11-02，匿名）**：单仓库首次采集 **6 次请求**（contributors / commits 各 1 页）。
剩余额度由 `GET /rate_limit` 给出，实测从 59/60 递减，与请求数一一对应。

### 2.2 字段口径

| 字段 | 口径（素材 §1 明确写死的部分） |
|---|---|
| `stargazers_count` | 仓库主页展示的 Star 数 |
| `forks_count` | Fork 数 |
| 最近提交时间 | 默认分支最新提交的 **committer date** |
| `archived` | GitHub 归档标志 |

> ★ 素材明确：「第三方聚合页面仅用于交叉检查，不替代 API 主字段」。

### 2.3 实测响应片段（原样引用素材）

素材 `watchlist星标活跃度复核.md` [1] 记录的 `deepseek-ai/DeepInfer` 响应：

> "stargazers_count": 24445, "forks_count": 2944, "archived": false, "pushed_at": "2026-10-25T11:59:27Z"

本项目 L0（2026-11-02）对 `deepseek-ai/DeepEP` 的实测：`stars=10403`、`forks=1535`、`created_at=2025-02-17T01:33:04Z`。

### 2.4 已知例外：归档仓库不返回统计字段

素材记录：`huggingface/text-generation-inference` 因 `archived=true`，本次 API 调用**未返回** Star / Fork 字段；素材**没有**用网页概览数回填，而是记作「API 未返回」。

> 这是本项目「未获得 + 原因」口径的直接来源：**宁可留空，不用口径不同的数补位**。

### 3.2 派生比值（本文计算，供预算估算用）

| 仓库 | meta / src | src token / 文件 | meta token / 路径 |
|---|---:|---:|---:|
| FlashMLA | **1.13%** | 2,359 | 17.3 |
| DeepInfer | **0.76%** | 2,427 | 15.6 |
| DeepEP | **9.36%** | 1,694 | 81.8 |
| verl | **1.34%** | 3,233 | 20.8 |
| 合计 | **1.48%** | 2,845 | 23.6 |

> ★ 区间 **0.76% – 9.36%** 与设计方案 §1.2 引用的「元数据层仅占源码 0.76%–9.36%」一致，互为印证。

**DeepEP 是异常点**：meta/src 高达 9.36%、每路径 81.8 token，是其余三个的 4–5 倍。素材未说明原因。**不推断**；若 L1/L3 用它做预算基准，应按最坏值而非均值。

### 3.3 口径边界（必须知道的"未获得"）

| 项 | 状态 | 原因 |
|---|---|---|
| tokenizer 名称 / 版本 | **未获得** | `token_result.json` 未记录；不同 tokenizer 下绝对值不可直接换算 |
| `src_tokens` 的计入范围 | **未获得** | 素材未说明是否排除 `tests/`、`examples/`、生成物、lock 文件 |
| `meta_tokens` 的构成 | **未获得** | 素材未说明是否含 README、目录树、文件路径列表、以及各占多少 |

| 与本文 §2 的 API 字段如何对齐 | **未获得** | token 素材是本地统计，未与 GitHub API 的 `size/文件树` 交叉验证 |

## 4. 外部工具（DeepWiki / Zread）

### 4.1 判定口径（fail-closed 的来源）

素材两组一致采用：

- **命中**：页面出现该仓库**真实的**目录、源码文件路径、模块组件或专属数字；
- **未命中**：只有仓库名 + `Index your code with Devin`、通用导航（探索/趋势/订阅/Ask AI）、或 `Repository processing failed`；
- **仅 URL 可访问不算命中**。

本项目据此落地为红线 #4：判定必须用「正文是否含 ≥N 个仓库内真实路径」（默认 N=3），**不得用"能否访问"**。

### 4.2 两组实测（2026-10-30，逐仓库明细为准）

**A. 推理 Infra 组**（10 新近 + 5 经典，合计 15）

| 分组 | 可判定 | DeepWiki 命中 | Zread 命中 |
|---|---:|---:|---:|
| 新近组 | 10 | **8**（80%） | **1**（10%） |
| 经典组 | 5 | **5**（100%） | **3**（60%） |
| 合计 | 15 | 13（86.7%） | 4（26.7%） |

未命中/异常明细：OpenLake（DeepWiki 模板页）、magnitude（两工具均无法判定）、Strata（Zread 处理失败）、DeepInfer / FreeToken（Zread 抓取失败）、ray（Zread 抓取失败）、vLLM（Zread 内容稀薄）。

**B. Agent 训练组**（10 个 2026 新建）

| 工具 | 命中 | 未命中 | 无法判定 |
|---|---:|---:|---:|
| DeepWiki | **10**（含弱 1：DataFlex-RL） | 0 | 0 |
| Zread | **8**（含弱 1：jev-ultrafast） | 1（DataFlex-RL） | 1（dsh-desktop 抓取失败） |

★ **素材汇总行与明细不符**：汇总写「Zread 8 强 + 1 弱 = 9 命中」，但逐仓库核对是 **7 强 + 1 弱 = 8 命中**（harness / openfang / laya / Agent-Reach / ECC / SkillSpector / multica 为强，jev 为弱）。因此该组 Zread 应为 **8/10 = 80%**（或 8/9 ≈ 89%，若排除无法判定项），**不是 90%**。本手册以明细为准并保留此更正。

### 4.3 反例片段（原样引用，L1 判定器要能区分这些）

| 仓库 | 工具 | 页面实际内容 | 判定 |
|---|---|---|---|
| `openlake-project/OpenLake` | DeepWiki | "Index your code with Devin"（只有仓库名 + 索引按钮） | **未命中**（模板页） |
| `Niko1221/Strata` | Zread | "We couldn't process Niko1221/Strata. This might be due to download issues…" | **未命中**（处理失败） |
| `vllm-project/vllm` | Zread | 标题 + 难度标签 + README 徽章入口，无模块结构 | **未命中**（内容稀薄） |
| `antirez/ds4` | DeepWiki | "The codebase is strictly C… ds4.c/h… Metal/CUDA/ROCm 后端" | **命中** |
| `antirez/ds4` | Zread | "engine core (ds4.c) handles model loading, tokenization, CPU reference code…" | **命中** |
| `haolpku/DataFlex-RL` | DeepWiki | 仓库专属页头 + Devin 提示，**无**目录/路径 | 命中（弱） |

### 4.4 两组结论相反，不可合并

- Agent 训练组：DeepWiki 10/10、Zread 8/10（★ 更正后）；
- 推理 Infra 组：新近组 DeepWiki 8/10、Zread 1/10。

差异的**可核实来源**：两组样本的 star 量级与语言/生态不同（Agent 组多 10 万+ star 的 TS/Python 项目；Infra 组多 200–2.8 万 star 的 C++/Rust/CUDA 项目）。素材本身也说明：**高 star 会触发自动索引**，因此该样本不能用于评估"长尾新项目"的索引风险。

> **禁止**把两组数字平均成"DeepWiki 命中率 90%"之类的单一指标——分母不同、构成不同。

## 5. Watchlist 复核（2026-10-30）

### 5.1 结果分层（素材 §1 全表，摘录关键列）

| 层级 | 仓库 | Star 区间 | 距最近提交 |

### 5.2 维护状态判定规则（素材版）

| 条件 | 判定 |
|---|---|
| 30 天内提交 | 活跃 |
| 30 – 180 天 | 放缓 |
| > 180 天 | 停止维护 |
| 官方宣布只收维护类 PR | 维护模式 |
| `archived=true` 且公告并存 | 归档 / 维护模式 |

> ★ 这与本项目代码的阈值**不一致**，见 §7-1。

### 5.3 可直接复用的结论

- **Star ≠ 活跃度**：DeepSeek-OCR 24,101 star 但 276 天无提交；EPLB 1,466 star 同属停止维护；两者 star 差 16.4 倍。
- **"有提交" ≠ "在扩展"**：AutoGen 仍有提交（2026-10-28），但 README 明确 maintenance mode。
- **"归档" ≠ "删除"**：TGI 归档后仍接收轻量维护 PR。

## 8. 维护规则

1. **只增不改**：新素材放 `docs/ref/`，在本文件 §0 素材清单登记后才可引用。
2. **每个数字带两样东西**：抓取时点 + 来源（素材文件名 / 章节 / API 端点）。
3. **拿不到就写进 §6**，不许用"大约""估计"填。
4. **发现素材自身矛盾**：保留双方原文，在 §7 登记，不静默取其一。
5. 本文件与 SSOT 冲突时，**以 SSOT 为准并向项目负责人上报**。

## 9. LLM 价格与 usage 口径（L1 新增）

> 本节只记**事实与来源**，预算策略见 `docs/成本预算.md`。

### 9.1 官方定价（核对 2026-11-03）

| 模型（API 名） | 版本 | 上下文 | 最大输出 | 缓存命中 | 输入未命中 | 输出 |
|---|---|---:|---:|---:|---:|---:|
| `deepseek-flash` | DeepSeek-V4.1-Flash-1017 | 1M | 384K | ¥0.04 | ¥2.00 | ¥8.00 |
| `deepseek-v4-pro` | （第三方称 V4-Pro-0813，**未获得官方确认**） | 1M | 384K | ¥0.30 | ¥9.00 | ¥27.00 |

- 表内为**高峰价**；低谷为其一半。高峰 = 工作日北京时间 09:00–12:00 / 14:00–18:00，**排除中国法定节假日**。

### 10.3 快照保留策略（T5，按可再生性分层）

唯一权威 = 设计方案 v1.3 §8.2（D15）。实现见 `osslens/retention.py`，配置见 `config.yaml → retention`：

| 层 | 路径 | 规则 |
|---|---|---|
| 不可再生真源 | `data/snapshots/**/external/`（`deepwiki.json` + `source.txt` + sha256） | **不删、不覆盖**；带来源四元组（红线 #13） |
| 真源 | `*.json` 快照元数据、`ledger/pool/costs` 三个 jsonl、`patterns/`、`reports/`、`config.yaml` | 代码白名单保护，`protected_paths()` 显式列出；清理清单永不入列 |
| 可再生缓存 | `data/snapshots/**/src/`、`data/llm_cache/` | 内容寻址去重（同 sha256 只存一份，`data/cache_objects/<sha2>/<sha256>`）+ 按期归档（`cache_keep_days`，默认 30） |

**体积估算（10 仓库 × 30 天）**，按现有真实产物外推：
- 单仓库单日 `external/` ≈ 196KB（`deepwiki` 正文 + `source.txt`）——**真源，不去重、不删**；
- 单仓库单日 `src/` ≈ 20 文件 / ≤512KB（`sources.max_total_bytes`）——缓存，可内容寻址去重；
- 保守上界（无去重）：`(196 + 512) KB × 10 × 30 ≈ 207 MB`；
- 内容寻址去重后：源码切片按 commit 复用，同 commit 跨 30 天**只存一份**，缓存层实质 ≈ `512KB × 10 = 5MB` 量级（+ 对象索引），真源 `196KB × 300 = 57.5MB` 仍随日期增长；
- 按期归档（30 天）把过期的 `src/` 移入 `data/cache_archive/`，工作集稳定在上界内。

**红线对应**：#6 的 append-only 清单只含 3 个 jsonl + `patterns/`，从未含 `snapshots` 整块 → 清理 `src/` / `llm_cache/` 不违规；去重/归档只作用于新增写入，已入 git 的 `external/` 零删除（`tests/test_l2.py::test_apply_dedupes_and_never_touches_sources` 断言真源字节不变）。
