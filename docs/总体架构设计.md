## 1. 整体描绘

### 1.1 一句话

一个**低成本、可长期运行**的开源项目分析系统：自动建候选池 → 人工/规则选定 → 分档分析 → 产出可核验的单项目报告 → 周期性横向抽象成规律库，使项目负责人在 **推理 / Infra / Agent** 等方向上逐步掌握架构范式、设计套路与技术选型能力。

### 1.2 四条价值主张（对应负责人第 3、4 点）

| #    | 主张                        | 落地机制                                                     |
| ---- | --------------------------- | ------------------------------------------------------------ |
| 1    | **低成本优先**              | 采集层尽量用免费源（GitHub API / DeepWiki / Zread / 确定性提取）；LLM 只在必要的判断位调用；档位与配额是成本闸门，不是质量旋钮 |
| 2    | **零 LLM 能做的绝不用 LLM** | 特征卡、依赖图、指标、模式召回全部确定性提取（🔒 决策 8、9）  |
| 3    | **量变到质变**              | 规律库四层阶梯 L1→L4 + 增量 merge（见 v0.1 §B–D）            |
| 4    | **可核验、可归档**          | 每条判断带代码证据；外部摘录带来源四元组与快照               |

### 1.3 非目标（明确排除）

- ❌ 不做通用爬虫平台，不做全文代码搜索引擎
- ❌ 不做需要长期维护的重跑对账（分析对象是快照 🔒 决策：收窄幂等）
- ❌ 不做 Web UI 交互编辑（只读视图，且最后做 🔒 决策 11）
- ❌ 不追求"自动判断项目价值"——**价值判断的信号只有项目负责人有**，系统只做预算兜底

### 1.4 成功的判据（建议，⚠️ 待负责人认可）

| 层级   | 判据                                                         |
| ------ | ------------------------------------------------------------ |
| 运行层 | 无人值守连续运行 8 周，无人工干预修复；成本台账可查          |
| 产出层 | 累计 ≥20 份单项目报告，每份附完整特征卡                      |
| 抽象层 | 规律库 L2 条目 ≥15（带反例位），L3 跨域范式 ≥5，L4 选型决策树 ≥1 版 |
| 个人层 | ⚠️ 无法由系统自评，需负责人周期性主观判断                     |

## 2. 端到端工作流

### 2.1 主流程（五段）

```
① 建池 collect       高频（日 / 2–3 日）   LLM 成本 = 0
   双通道：热点（trending + 增速） / 经典（star 量级 + 年龄 + Used by + watchlist）
   → pool.jsonl（append-only）

② 观察与筛选        观察期 3–7 天（热点通道）  LLM 成本 = 0
   增速拐点 / trending 上榜 → 区分真热度与噪声

③ 选定（**写实**）  负责人直接指定 `analyze` 的 repo slug   LLM 成本 = 0
   ★ 不设 `select` 命令、不写 `chosen.jsonl`；无「规则自动选定」的写入方。
   ★ `pool eligible` 只**打印**候选（放行判定），**不等于**自动触发 `analyze`（Q1：设计为本地手动）。

④ 深挖 analyze      每周 1 个             LLM 成本集中在此
   采集 → 特征提取（零 LLM）→ 档位闸门 → LLM 分析 → 渲染 MD + 特征卡

⑤ 抽象 abstract     簇内样本达标时触发    LLM 成本 = 1 次 / run
   召回（零 LLM）→ op 列表 → 落到规律库条目修订
```

### 2.2 第 ④ 步内部展开

```
4.1 冻结快照       commit_sha + analyzed_at；外部文档存 _sources/ 并记 hash
4.2 确定性提取     特征卡 / 依赖图 Mermaid / 指标 / 目录与入口结构   [零 LLM]
4.3 外部采集       DeepWiki（MCP）→ Zread（llms.txt）→ README 兜底   [fail-closed]
4.4 档位闸门       通道基线 → 周配额 → 预算预估拦截（不中途降质）
4.5 LLM 分析       按通道选模板：热点=值不值得跟 / 经典=值不值得学
4.6 渲染           报告 MD + 特征卡 YAML + 外部资料块（结构分离）
4.7 记账           cost.jsonl + runs.jsonl；index.db 重建
```

### 2.3 成本分布（⚠️ 推算，非实测）

| 阶段                               | LLM 调用      | 说明                     |
| ---------------------------------- | ------------- | ------------------------ |
| 建池 / 筛选 / 特征 / 依赖图 / 召回 | **0**         | 全确定性                 |
| off 档分析                         | **0**         | 体检报告                 |
| fast 档                            | 1–2 次 / 项目 | ⚠️ 次数待实测后定         |
| strong 档                          | 3–6 次 / 项目 | ⚠️ 同上                   |
| 簇内抽象                           | 1 次 / run    | 输入为结构化摘要         |
| 跨域抽象                           | 1 次 / run    | 输入为 L2 摘要，token 小 |

## 3. 架构设计

### 3.1 分层

```
┌─ 编排层 Orchestrator ─────────────────────────────┐
│  select / tier_gate / quota / budget / idempotency │
└───────────────┬───────────────────────────────────┘
┌─ 采集层 Collectors ─┐ ┌─ 提取层 Extractors ─┐
│ github_api          │ │ feature_card          │
│ trending            │ │ dependency_graph(Mmd) │
│ deepwiki / zread    │ │ metrics / entrypoints │
│ source_files        │ └───────────────────────┘
└─────────────────────┘
┌─ 分析层 Analyzers ──┐ ┌─ 抽象层 Abstraction ─┐
│ off  / fast / strong│ │ recall（零 LLM）      │
└─────────────────────┘ │ cluster_run / cross   │
                        │ merge(op 追加修订)    │
                        └───────────────────────┘
┌─ 真源层 Sources（append-only）─────────────────┐
│ *.jsonl / reports/ / patterns/ / _sources/     │
└────────────────────────────────────────────────┘
┌─ 索引层 index.db（可重建缓存）────────────────┐
└────────────────────────────────────────────────┘
┌─ 渲染层 Render ────────────────────────────────┐
│ MD 模板（按通道两套）/ index / Mermaid 内嵌     │
└────────────────────────────────────────────────┘
```

### 3.2 真源 vs 缓存（🔒 红线 1）

| 类型     | 内容                                                         | 可否丢弃 |
| -------- | ------------------------------------------------------------ | -------- |
| **真源** | `pool.jsonl` `chosen.jsonl` `runs.jsonl` `cost.jsonl` `patterns/entries.yaml` `reports/**` `_sources/**` `config/scope.yaml` | ❌ 不可   |
| **缓存** | `index.db`、trending 抓取缓存、GitHub API 响应缓存           | ✅ 可重建 |

### 3.3 目录结构（草案）

```
config.yaml           # ★ 唯一配置真源（原型已实跑）
  ├─ focus_domains / watchlist        # 方向配置化（不另设 scope.yaml）
  ├─ pool.*                          # 双通道阈值 + 观察期
  ├─ depth.weekly_quota / budget.*   # 周配额 + token 闸门
  └─ llm.{api_key_env, base_url_env, models.{fast,strong}, price_table}
src/
  collectors/       github_api / trending / deepwiki / zread / source_files
  extractors/       feature_card / dependency_graph / metrics
  analyzers/        off / fast / strong
  abstraction/      recall / cluster_run / cross_domain_run / merge
  orchestrator/     select / tier_gate / quota / budget / idempotency
  render/           templates / index / mermaid
data/
  pool.jsonl  chosen.jsonl  runs.jsonl  cost.jsonl  index.db
reports/<owner>__<repo>/<date>-<sha>/
  report.md  feature-card.yaml
patterns/
  entries.yaml      # 模式条目（追加式修订，永不删）
  runs.jsonl
_sources/<repo>/<date>-<hash>.md
```

### 3.4 幂等（🔒 已收窄定义）

**幂等键** = `commit_sha` + 外部快照 hash 列表 + `template_version` + `extractor_version`
**定义**：同一幂等键重跑 → 产出字节一致。
**用途**：让重跑 diff 可归因（区分"我改了模板"还是"上游变了"），不是每周对账。

### 3.5 降级矩阵（🔒 红线 2、5）

| 故障                   | 行为                                                         | 退出码 |
| ---------------------- | ------------------------------------------------------------ | ------ |
| 无 LLM 密钥 / 配额耗尽 | 全部降级 **off 档**，报告中留痕                              | 0      |
| LLM 连续失败 ≥N        | 熔断 → off 档 + 告警留痕                                     | 0      |
| DeepWiki 未命中        | **fail-closed**：标记 `external: none`，**绝不生成模板化伪页面** | 0      |
| Zread 不可用           | 同上，独立判定                                               | 0      |
| GitHub API 限流        | 降频重试；仍失败 → 本轮建池标 degraded 跳过                  | 0      |
| trending 抓取失败      | 本轮跳过，不影响已入池数据                                   | 0      |

## 4. 技术选型

> 每项标注置信度。⚠️ 项表示"暂按此写，需实测或负责人拍板"。

### 4.1 确定度高的选型

| 领域       | 选型                                                         | 置信 | 理由                                                         |
| ---------- | ------------------------------------------------------------ | ---- | ------------------------------------------------------------ |
| 语言       | **Python 3.11+**                                             | 高   | GitHub API / LLM SDK / tree-sitter 生态最全                  |
| 真源格式   | **Markdown + YAML front-matter**；台账用 **JSONL append-only** | 高   | 🔒 决策 11（MD 是真源）；JSONL 天然 append-only、可 diff、可 git 版本化 |
| 可重建索引 | **SQLite**                                                   | 中高 | 零运维、单文件、可删可重建；真源仍在 JSONL/MD                |
| 依赖图     | **Mermaid**（内嵌 MD 代码块）                                | 高   | 🔒 决策 9；GitHub / Obsidian 原生渲染，输出自包含             |
| 代码解析   | **tree-sitter**（主）+ 正则（兜底）                          | 中高 | import/依赖可确定性提取，零 LLM；正则兜底免依赖膨胀          |
| LLM 接入   | **OpenAI 兼容协议 SDK** + provider 可配置                    | 中高 | 换 provider 不改代码；⚠️ 具体 provider/模型待负责人定         |
| 配置       | **YAML**（`config/*.yaml`）                                  | 高   | 范围配置化要求（v0.1 §A）                                    |
| 测试       | **pytest**；幂等用固定 commit + 冻结快照做字节比对           | 高   | 🔒 幂等定义可直接写成断言                                     |

| #    | 项                    | 暂定默认值                                            | 决定判据                                                     |

## 5. 接口与命令集（草案）

```bash
python -m osslens pool add owner/repo            # 建池（零 LLM）
python -m osslens pool list                     # 查看候选池（hot / classic 分通道）
python -m osslens pool eligible                # 打印深挖候选（★ 只打印，不自动分析）
python -m osslens analyze owner/repo --depth off|fast|strong   # 本地手动，唯一花钱环节
python -m osslens abstract --cluster inference # 簇内抽象（阈值触发）
python -m osslens abstract --cross             # 跨域抽象：★ Q5 已裁决接线，实现轮落地（当前未接线）
python -m osslens cost                        # 成本台账
python -m osslens site [--check]              # 静态站点 / 只比对不写盘
★ 草案命令 `select` / `feature-card` / `verify --idempotent` / `index rebuild` 现实未实现；
  真源为 append-only JSONL，不设 `index.db`（见 §0 对照表）。
```

**每个命令的输出约定**：退出码 0 表示"完成（可能 degraded）"；非 0 才是真失败。
