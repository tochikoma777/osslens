## A. 分析范围配置化（不再硬编码方向）

**原则（设计意图，不可违背）**：代码里不出现任何具体方向常量。方向、watchlist、排除项**全部来自配置**。

**★ 落地形态以原型 `config.yaml` 为准**：

```yaml
focus_domains:        # 方向清单；新增方向 = 加一项，不改代码
  - inference
  - ai_infra
  - agent
watchlist: []         # 关注清单（意图层，非入口过滤器）
```

**约束（这些是规格，不随字段名变）**

| # | 规则 |
|---|---|
| 1 | `domain.id` 是规律库**主聚类键**；改名需走迁移，旧 id 作为 alias 保留 |
| 2 | 新增方向 = 加配置，**不改代码** |
| 3 | 模板选择由 `channel` 决定（热点→值不值得跟；经典→值不值得学），与 `domain` 解耦 |
| 4 | 方向增删**不影响已产出条目**：旧条目保留其 `cluster` 值 |
| 5 | ★ **watchlist 是意图层，不是入口过滤器**（设计方案 §6.4）：只打标 / 定通道基线 / 参与排序，**不决定仓库是否入池** |

> ⚠️ 早期草案曾提议独立的 `config/scope.yaml`（domains + watchlist + exclude 三段）。
> 该提议**不再作为结构规定**——原型已用 `config.yaml` 的 `focus_domains` + `watchlist` 落地并实跑，
> 维持两份结构会形成两处真相。此处仅保留其设计意图。

## B. 规律库：四层抽象阶梯（对应"纵向"提升）

| 层 | 内容 | 产出方式 | 频率 |
|---|---|---|---|
| **L1 结构事实** | 单项目可核验事实（特征卡 + 代码证据） | 零 LLM，确定性提取 | 每次分析 |
| **L2 簇内模式** | 同方向项目的共性、套路、取舍 | 批量抽象（LLM） | 簇内样本达阈值 |
| **L3 跨域范式** | 跨方向通用的架构范式、模式轴 | 批量抽象（LLM，输入为 L2 摘要） | L2 达阈值 |
| **L4 设计原则** | 选型决策树、开发路线套路、反模式清单 | 汇总 + 人工抽检 | 季度级 |

**下钻链**：L4 每条必须能下钻到 L3 → L2 → L1 代码证据。不能下钻的条目按本质论处理，禁止入库。

**可证伪性随层级递严**

| 层 | 判据 |
|---|---|
| L1 | 翻代码，非此即彼 |
| L2 | 必须带反例位 |
| L3 | 必须给出 ≥2 个方向的跨域证据 |
| L4 | 必须给出适用边界 + 反模式清单 |

## C. 聚类：一个主键 + 软标签

| 项 | 取值 | 用途 |
|---|---|---|
| **主聚类键** | `domain.id` | 稳定、人可读、可枚举。决定"同类聚类抽象"的边界 |
| **软标签** | 特征卡派生的结构标签（`cache-reuse` / `sharding` / `kernel-fusion` …） | 多值，用于**跨域召回** |

一个项目属于**一个主簇**，可带**多个软标签**——兼顾"同类深挖"与"跨域发现共性"。

## D. 增量 merge 机制（核心）

**规律库的基本单位不是"一版抽象文档"，而是带稳定 ID 的条目 + 追加式修订。**
新增同类项目只产生 **op**，不重开一次抽象。

**条目操作**（每次 run 产出 op 列表，不是新文档）

| op | 含义 |
|---|---|
| `add` | 新增条目 |
| `strengthen` | 新增独立证据，置信度上调 |
| `weaken` | 出现反例但未证伪 |
| `refine` | 适用条件 / 表述收窄或修正 |
| `falsify` | 证伪，标记失效（**保留，不删**） |
| `merge` / `split` | 粒度调整（旧 ID 保留为 alias） |

**簇内 run 流程**

```
1. 新项目入池 → 提取特征卡（零 LLM）
2. 确定性召回：特征卡 ↔ 已有条目 tags / applicability → 命中 / 未采用 / 无匹配
3. 未采用 = 反例候选，记入该条目 evidence（kind: 反例）
4. 簇内新增样本数 ≥ 阈值 → 触发 cluster-abstraction run
5. run 输入 = 上次该簇抽象结果（结构化摘要）+ 本次新增样本（不全量重喂）
6. run 输出 = op 列表 → 落到条目 revision，append-only 留痕
7. 每 5 次增量 run → 一次全量 reconcile run（喂该簇全部样本，防漂移）
```

**两条硬规则**

| # | 规则 | 理由 |
|---|---|---|
| 1 | 增量 run 不全量重喂 | 省 token，且保证抽象连续性 |
| 2 | 失效条目只标 `falsified`，永不删除 | "为什么这条不成立"与正例信息量相等 |

## E. 触发规则与成本（默认参数，⚠️ 未实测，可调）

| 触发 | 默认阈值 | LLM 调用 |
|---|---|---|
| 簇内抽象 | 同簇新增 ≥6 个项目 | 1 次 / run |
| 全量 reconcile | 每 5 次增量 run | 1 次 / run |
| 跨域抽象（L3） | L2 条目 ≥8，或每 4 次簇内 run | 1 次 / run（输入为 L2 摘要，token 小） |
| 设计原则（L4） | 季度级 | 1 次 / run |

- 召回零 LLM（沿用设计方案 §7.4-3）。
- 抽象 run 的输入是**结构化摘要**，不是散文 MD → token 远低于重读全文。

## F. 数据结构

**模式条目**（真源，YAML 块内嵌于 MD）

```yaml
id: P-001                    # 稳定 ID，永不复用
level: L2
cluster: inference
tags: [cache-reuse, 显存, 调度]
status: active               # active | weakened | falsified
statement: 瓶颈是重复计算时，采用前缀复用
applicability: [前缀重叠率高, 不锁定特定硬件]
evidence:                    # 追加式，永不删
  - repo: vllm-project/vllm
    kind: 正例
    path: vllm/attention/...
    commit: abc1234
  - repo: huggingface/text-generation-inference
    kind: 反例
    note: 无独立设计，生态优势耗尽后停止维护
confidence: 中
falsification: 出现高前缀重叠但未采用前缀复用且无性能劣势的项目
revision: 3
```

**run 记录**（append-only JSONL 真源）

```json
{"run_id":"R-007","type":"cluster-abstraction","cluster":"inference","trigger":"新增样本 6 (>=6)","input_projects":["owner/a","owner/b"],"input_patterns":["P-001","P-004"],"ops":[{"op":"strengthen","id":"P-001","reason":"第 3 个独立证据"},{"op":"weaken","id":"P-004","reason":"新增反例"}],"llm_calls":1,"created_at":"2026-10-31"}
```

## G. 每轮抽象 run 后的自检（必答）

| # | 自检 |
|---|---|
| 1 | 本轮是否产出可下钻到代码证据的条目？（否则是本质论，禁止入库） |
| 2 | 本轮是否新增了反例？（无反例 = 幸存者偏差风险） |
| 3 | 本轮是否有跨域证据？（决定能否升到 L3） |
| 4 | 最需要人工核验的是哪一条？（红线 11 抽检位，必填） |
